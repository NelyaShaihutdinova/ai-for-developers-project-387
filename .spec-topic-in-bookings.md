# Spec: Тема разговора в записи на встречу (#2)

## Problem Statement

Владелец календаря видит в списке предстоящих встреч только дату, время, тип встречи, имя и email гостя. Без понимания темы разговора владелец не может подготовиться к встрече — неясно, о чём пойдёт речь, какие материалы нужны, какой контекст стоит вспомнить заранее.

## Solution

Гость получает возможность указать короткий заголовок темы при бронировании (опционально). Тема отображается в таблице владельца на Dashboard рядом с остальными данными записи. Обратная совместимость сохраняется: старые записи без темы продолжают корректно отображаться.

## User Stories

1. As a guest, I want to optionally enter a meeting topic when booking, so that the calendar owner knows what the meeting is about
2. As a calendar owner, I want to see the meeting topic in my bookings table on the Dashboard, so that I can prepare for each upcoming meeting
3. As a guest, I want to see a character counter (0/200) on the topic field, so that I know the length limit
4. As a calendar owner, I want to see an empty cell or placeholder when a booking has no topic, so that the table remains clear for legacy bookings
5. As a developer, I want the topic field to be optional in the API contract, so that existing integrations and old bookings remain backward-compatible

## Implementation Decisions

### Schema change (drizzle)

Добавить опциональное поле `topic` в таблицу `bookings`:

- Column: `text('topic')` (nullable, no `.notNull()`)
- Миграция через `drizzle-kit generate`
- Существующие записи получат `NULL` — таблица в Dashboard должна это корректно отображать (пустая ячейка)

### API contract (TypeSpec → OpenAPI → SDK)

Контрактная цепочка сохраняется. Изменения **только** в TypeSpec, OpenAPI и SDK перегенерируются автоматически через `mise run generate:api`.

**`BookingCreate`** — добавить опциональное поле:

```
topic?: string;  // max 200 chars, optional
```

**`Booking`** — добавить поле:

```
topic: string | null;
```

**`BookingWithTypeName`** — добавить поле:

```
topic: string | null;
```

### Backend validation

В `POST /api/bookings` handler:

- Zod-схема: `topic: z.string().max(200).optional().nullable()` (или `.optional().or(z.literal(''))` если приходит пустая строка)
- Значение по умолчанию: `null` если поле отсутствует или пустая строка
- Валидация: если topic предоставлен — max 200 символов

**`GET /api/bookings`** — включить `topic` в SELECT из `bookings.topic` в возвращаемый объект `BookingWithTypeName`.

### Frontend: форма гостя (MeetingsPage)

- Добавить `TextInput` с label «Тема» после поля Email, перед кнопкой «Записаться»
- Компонент Mantine `TextInput` с `maxLength={200}`
- Счётчик символов `0/200` через Mantine `Input.Wrapper` с `description` или кастомный рендер
- Поле опциональное — без валидации `required`
- Пустая строка или `undefined` отправляется в API как `null` / omit
- Обновить `handleBooking` — включить `topic` в body запроса `bookingsCreate`
- Обновить `confirmedBooking` state и экран подтверждения — отобразить тему если указана

### Frontend: таблица владельца (DashboardPage)

- Добавить колонку «Тема» в таблицу «Предстоящие встречи» между «Тип» и «Имя гостя»
- Заголовок: `<Table.Th>Тема</Table.Th>`
- Ячейка: `{b.topic || '—'}` (placeholder для записей без темы)
- Обновить `colSpan` в пустой-строке с 6 на 7

### Colspan in Dashboard empty row

Текущий `colSpan={6}` → `colSpan={7}` (добавлена колонка «Тема»).

### Backward compatibility

- `topic` nullable в БД — старые записи остаются валидными
- `topic` optional в `BookingCreate` — старые клиенты (если появятся) продолжат работать
- UI отображает `—` для пустых значений

### Order of changes

1. TypeSpec (`backend/typespec/main.tsp`) — добавить `topic` в модели
2. `mise run generate:api` — перегенерировать OpenAPI + frontend SDK
3. Drizzle schema + миграция — добавить колонку `topic`
4. Backend handler (`POST /api/bookings`, `GET /api/bookings`) — валидация + projection
5. Frontend: MeetingsPage — поле ввода темы в форму
6. Frontend: DashboardPage — колонка «Тема» в таблице

## Testing Decisions

### Backend tests

- `POST /api/bookings` — успешное создание с topic (в пределах 200 символов)
- `POST /api/bookings` — успешное создание без topic (null/undefined/empty)
- `POST /api/bookings` — rejection при topic > 200 символов (400)
- `GET /api/bookings` — возвращает topic для записей с темой
- `GET /api/bookings` — возвращает `null` для записей без темы (legacy)

Prior art: existing booking tests in `backend/src/__tests__/` (supertest-based).

### Frontend tests

- DashboardPage: таблица содержит колонку «Тема», ячейки отображают topic или `—`
- DashboardPage: `colSpan` пустой строки = 7
- MeetingsPage: поле «Тема» присутствует в форме, опциональное
- MeetingsPage: счётчик 0/200 отображается
- MeetingsPage: отправка формы с topic и без topic

Prior art: existing `DashboardPage.test.tsx`, `HomePage.test.tsx` (vitest + jsdom).

### E2E

- Пройти полный флоу бронирования с указанием темы → проверить, что тема появилась в Dashboard

Prior art: existing Playwright e2e tests (`mise run test:e2e`).

## Out of Scope

- Редактирование темы после создания записи
- Поиск/фильтрация записей по теме на Dashboard
- Валидация topic на уникальность или по содержанию
- Отображение темы в email-уведомлениях (если будут добавлены)
- Многострочный ввод / textarea — только однострочный TextInput, короткий заголовок

## Further Notes

- timezone: все даты в UTC, форматирование на фронтенде через `Europe/Moscow`
- working hours: 09:00–18:00 MSK (UTC+3), слоты с шагом 15 мин
- booking window: 14 дней от завтра
- `topic` — plain text, без markdown/HTML
