# Spec: Тема записи в форме бронирования и на дашборде (#13)

## Problem Statement

Владелец календаря не видит, о чём пойдёт встреча, в списке предстоящих записей. На дашборде отображаются только дата, время, тип встречи, имя гостя, email и длительность — без понимания темы разговора приходится связываться с гостем отдельно.

## Solution

Гость вводит тему разговора при бронировании (опционально, рядом с именем и email). Тема сохраняется в записи и отображается на дашборде владельца в таблице предстоящих встреч.

## User Stories

1. As a **гость**, I want to optionally enter a meeting topic when booking, so that the owner knows what the meeting is about
2. As a **гость**, I want to leave the topic field empty, so that I'm not forced to fill it in if I don't want to
3. As a **гость**, I want to enter up to 200 characters in the topic field, so that I can describe the purpose concisely
4. As a **владелец календаря**, I want to see the topic column in the bookings table on the dashboard, so that I know what each meeting is about at a glance
5. As a **владелец календаря**, I want to see an empty value (dash or blank) when no topic was provided, so that the table still looks clean for older bookings

## Implementation Decisions

### Contract chain: TypeSpec → OpenAPI → SDK

The feature touches the full contract chain. All changes propagate through generation:

| Layer | Change | Source |
|---|---|---|
| **TypeSpec** (`backend/typespec/main.tsp`) | Add `topic?: string` to `BookingCreate` and `BookingWithTypeName` | Manual edit |
| **OpenAPI** (`backend/openapi/openapi.yaml`) | Regenerated | `@typespec/openapi3` |
| **Frontend SDK** (`frontend/src/api/generated/`) | Regenerated | `@hey-api/openapi-ts` |

**TypeSpec changes:**

```
model BookingCreate {
  meetingTypeId: int32;
  startAt: string;
  guestName: string;
  guestEmail: string;
  topic?: string;         // new — optional, max 200 chars (validated server-side)
}

model BookingWithTypeName {
  id: int32;
  meetingTypeId: int32;
  meetingTypeName: string;
  startAt: string;
  endAt: string;
  guestName: string;
  guestEmail: string;
  topic: string;          // new — nullable/empty-string for existing bookings
  createdAt: string;
}
```

### Backend

- `POST /api/bookings` — accept optional `topic` in request body, store it
- `GET /api/bookings` — return `topic` in `BookingWithTypeName` (empty string if null)
- Existing bookings without a topic return `""` (empty string), not `null`

### Frontend — MeetingsPage (booking form)

- Add optional `TextInput` for `topic` below `guestEmail`, above the submit button
- Label: «Тема», placeholder: «О чём хотите поговорить?»
- Max length: 200 characters (use Mantine `maxLength` prop)
- No validation — field is optional, empty is valid
- Pass `topic` in the `bookingsCreate` call
- Confirmation screen: display topic if provided (between email and the "Записаться ещё" button)

### Frontend — DashboardPage (owner dashboard)

- Add «Тема» column to the bookings table (between «Email» and «Длительность»)
- Display `b.topic` (or `—` if empty string) in each row
- Update `colSpan` in the empty-state row from 6 to 7

### DB migration

- Add `topic` column to the `bookings` table (`TEXT`, `NOT NULL`, `DEFAULT ''`)

### Seams for testing

- **Single seam**: the `POST /api/bookings` endpoint — accepts `topic`, stores it, returns it in `GET /api/bookings`
- All other changes are presentational (frontend form + table) driven by the API contract

## Testing Decisions

- **Backend**: Add test for `POST /api/bookings` with and without `topic` — verify 201 response includes topic, empty topic is accepted, topic > 200 chars returns 400
- **Backend**: Add test for `GET /api/bookings` — verify `topic` field is present in `BookingWithTypeName`
- **Frontend**: Unit test for MeetingsPage — verify topic field renders, is optional, maxLength enforced
- **Frontend**: Unit test for DashboardPage — verify "Тема" column renders, empty topic shows as `—`
- Prior art: existing booking tests in `backend/src/routes/bookings.test.ts`, frontend component tests in `frontend/src/pages/`

## Out of Scope

- Редактирование темы владельцем на дашборде
- Валидация темы (запрещённые слова, обязательность)
- Поиск/фильтрация записей по теме
- Отображение темы в письмах-подтверждениях (email-уведомления пока не реализованы)
- Многострочный ввод темы — только однострочный TextInput

## Further Notes

- Existing bookings (created before this change) will have `topic: ""` — the dashboard should render this as `—` for visual clarity
- The 200-character limit matches typical "subject line" conventions and keeps the dashboard column readable
